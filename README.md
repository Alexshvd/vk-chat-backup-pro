# VK Chat Backup Pro

**Бесплатный проект с открытым исходным кодом.** Локальный архив переписки ВК: выгрузка диалога по ссылке, сохранение доступных вложений и просмотр сообщений в интерфейсе, похожем на окно переписки ВК.

## Начните здесь

**Для Windows без Python:** скачайте ZIP приложения из [beta-релиза](https://github.com/Alexshvd/vk-chat-backup-pro/releases/tag/v1.0.0-beta.1), распакуйте всю папку и дважды нажмите **VkChatBackupPro.exe**. Оставьте открывшееся окно работающим. Windows может показать предупреждение о неподписанном приложении: подписи издателя у первого beta-выпуска нет.


Если локальная копия уже подготовлена:

1. Откройте папку приложения и дважды нажмите **start-local.cmd**. Оставьте окно работающим. Если браузер не открылся сам, перейдите на [http://127.0.0.1:5000](http://127.0.0.1:5000).
2. Откройте приложение в браузере, где вы вошли в ВК. В меню нажмите **«Скачать диалог»**, затем **«Подключить браузер»** и выполните подсказки. Если браузер уже подключён, этот шаг можно пропустить.
3. Откройте нужную переписку на сайте ВК, нажмите **Ctrl+L**, затем **Ctrl+C**. Вернитесь в приложение и вставьте ссылку в поле через **Ctrl+V**.
4. Нажмите **«Скачать диалог»**, дождитесь завершения и нажмите **«Открыть переписку»**.

Сохранённые переписки находятся в разделе **«Диалоги»**. Фото увеличиваются по нажатию; **«Показать вложения»** открывает библиотеку файлов диалога. В настройках можно выбрать видео, музыку и голосовые сообщения. Для обычного скачивания технические параметры менять не нужно.

Пока идёт скачивание, оставьте компьютер, приложение и браузер с ВК включёнными. [Пошаговая инструкция для локальной копии](LOCAL-START.md).

## Что изменилось в форке

| Область | Изменения |
| --- | --- |
| Выгрузка сообщений | Ссылка на диалог → получение истории через помощник браузера → сохранение JSON → Markdown и вложения. Ручной перенос JSON больше не нужен для этого способа. |
| Работа с браузером | Текущий браузер определяется автоматически. Подключение открывается в той же вкладке и профиле; для выгрузки используется уже подключённый браузер. Нужная вкладка ВК переиспользуется или открывается новая. |
| Просмотр архива | Окно переписки, входящие и исходящие сообщения, пересылки и ответы, поиск, переход к дате, увеличение фото и встроенные плееры. |
| Библиотека вложений | Кнопка «Показать вложения» рядом с редактором файлов: фото, видео, аудио и документы диалога, поиск, фильтры, размеры и переходы к сообщениям. Общий файл отображается один раз со списком сообщений, где он используется. |
| Фотографии | Исправлен выбор миниатюры у старых фото с нулевыми размерами. Выбирается наибольшая доступная копия, ранее сохранённые уменьшенные фото можно автоматически заменить. |
| Видео | Выбор наибольшего переданного разрешения MP4, поддержка прямой ссылки `src`, резервного CDN и догрузки пропущенных файлов. |
| Аудио | Загрузка музыки, голосовых MP3/OGG и старых голосовых в документах. Поддержка доступных HLS-потоков и плееров в архиве. |
| Скачивание | Параллельная загрузка крупных MP4, сохранение завершённых частей, проверка диапазонов и размера файла, отображение прогресса и скорости. |
| Повторы видео | Общий индекс всех диалогов по ID вложения ВК и разрешению. Уже сохранённое видео используется повторно без скачивания, даже при изменившихся ссылках. |
| Повторный экспорт | Уже сохранённые сообщения пропускаются при выгрузке по ссылке. Восстановление фото, видео и аудио сохраняет предыдущие версии изменённых файлов. |
| Длинные пути | Расчёт длины имён с учётом полного пути и UTF-16, сохранение идентификатора сообщения и суффиксов частей. |

Сохранены возможности оригинала: экспорт в Markdown с авторами и таблицей источников, вложения пересланных сообщений, фильтры, переименование, удаление и группировка файлов в веб-редакторе.

## Быстрый старт на Windows

Приложение открывается в обычном браузере. Выберите тот, где вы пользуетесь ВК. Адрес по умолчанию — `http://127.0.0.1:5000`; помощник также работает на другом порту локального сервера. Ручная обработка JSON доступна без помощника.

### 1. Установить зависимости и запустить приложение

Скачайте исходники форка в `C:\VK`. В PowerShell выполните:

```powershell
cd C:\VK
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Для **первого запуска новой копии** создайте настройки из примера:

```powershell
Copy-Item config.example.json config.json
```

Если приложение уже использовалось, сохраните свои настройки в `config.json`.

Запуск без отладчика и автоматического перезапуска сервера:

```powershell
.\.venv\Scripts\python.exe run-local.py
```

Также можно использовать `start-local.cmd`. Оставьте процесс приложения запущенным и откройте [страницу экспорта](http://127.0.0.1:5000/export).

### 2. Подключить свой браузер

1. Откройте страницу **«Скачать диалог»** в браузере, где вы уже вошли в ВК. Браузер определяется автоматически.
2. Нажмите **«Подключить браузер»**. Страница настройки откроется в этой же вкладке. Подходящая инструкция выбирается автоматически.
3. Установите подходящую сборку помощника по инструкции на странице настройки.
4. Вернитесь на страницу подключения и нажмите **«Помощник установлен — подключить»**.

| Браузер | Помощник и установка |
| --- | --- |
| Google Chrome | Chromium-сборка; `chrome://extensions`, режим разработчика, загрузка распакованной папки. Реальная выгрузка проверена. |
| Microsoft Edge | Chromium-сборка; `edge://extensions`. |
| Opera / Opera GX | Chromium-сборка; `opera://extensions`. |
| Brave | Chromium-сборка; `brave://extensions`. |
| Vivaldi | Chromium-сборка; `vivaldi://extensions`. |
| Яндекс Браузер | Chromium-сборка; `browser://extensions`. |
| Firefox 128+ | Отдельная Firefox-сборка; временная загрузка ZIP через `about:debugging#/runtime/this-firefox`. |
| Safari, другие браузеры без подходящего помощника | Ручная выгрузка JSON через консоль ВК и загрузка файла в приложение. |

Chromium-сборку можно загрузить из папки `BrowserExtension` или скачать ZIP на странице подключения и распаковать его. Для Firefox скачайте предложенный ZIP и выберите его в **«Загрузить временное дополнение»**. Firefox использует фоновый скрипт, Chromium — service worker; логика помощника общая.

Временное дополнение Firefox удаляется при перезапуске браузера. Для постоянной установки и распространения потребуется подписанный пакет: [инструкция Mozilla](https://extensionworkshop.com/documentation/develop/temporary-installation-in-firefox/). Минимальная версия Firefox 128 связана с используемым выполнением скрипта в контексте страницы: [совместимость API](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/scripting/ExecutionWorld).

Помощник читает выбранный диалог через `messages.getHistory` в текущей сессии ВК и передаёт результат локальному приложению. Он не копирует пароль или cookies. Доступ ограничен доменами ВК и локальными адресами `127.0.0.1` / `localhost`. Подключение привязывается к адресу и порту выбранного локального сервера.

Другие браузеры на Chromium используют ту же сборку при поддержке необходимых API. Их совместимость, а также реальная выгрузка в Firefox, Edge, Opera, Brave, Vivaldi и Яндекс Браузере отдельно не проверялись.

### Способ без расширения

Для браузера без готового помощника раскройте **«Дополнительно: ручная выгрузка и работа с файлами»** на странице экспорта. Укажите Peer ID, скопируйте скрипт и выполните его в консоли ВК в своём браузере. Загрузите полученный JSON в приложение и нажмите **«Подготовить сообщения»**. Этот способ требует работающего сайта ВК, JavaScript и доступа к консоли разработчика, но не зависит от формата расширений браузера.

### 3. Скачать диалог

1. В подключённом браузере откройте нужный диалог ВК и скопируйте его ссылку, например `https://vk.ru/im/convo/123456789`.
2. Вставьте ссылку в верхнее поле страницы **«Скачать диалог»**.
3. Нажмите **«Скачать диалог»**. История сохранится в JSON, затем начнётся обработка сообщений и вложений.
4. После завершения нажмите **«Открыть переписку»**.

Оставьте подключённый браузер открытым до получения всей истории. Скачивание вложений продолжается отдельным процессом, даже если закрыть вкладку приложения. Состояние задачи сохраняется при перезапуске веб-сервера. Для остановки используйте кнопку **«Остановить»**; сохранённые файлы остаются в архиве.

## Просмотр и редактирование

На странице **«Диалоги»** выберите переписку. В просмотрщике доступны поиск по истории, включая пересылки, переход к дате, подгрузка предыдущих сообщений, увеличение фотографий и воспроизведение сохранённых видео и аудио.

Кнопка обновления добавляет доступные сообщения во время экспорта, сохраняя место чтения. **«Дополнительно → Редактор файлов»** открывает редактор Markdown с переименованием, перемещением и удалением файлов.

## Основные настройки

| Параметр | Назначение |
| --- | --- |
| `export_root` | Корневой каталог архива. Выбирается в настройках; пустое значение использует папку рядом с приложением. |
| `download_short_video`, `download_long_video` | Отдельные переключатели скачивания коротких и длинных видео. |
| `long_video_threshold` | Граница между двумя категориями видео в секундах; это **не максимальная разрешённая длительность**. |
| `download_audio` | Скачивание доступной музыки. |
| `download_voice_messages` | Скачивание голосовых сообщений. |
| `overwrite_existing_md` | Пересоздание уже существующих Markdown-файлов при ручной генерации. |
| `overwrite_existing_original_message_json` | Перезапись извлечённых JSON при ручной генерации. |
| `min_cid_by_peer_id`, `min_date_by_peer_id` | Фильтры сообщений для отдельных диалогов. |
| `dialog_name_by_peer_id` | Пользовательские названия каталогов диалогов. |

Чтобы скачивать видео любой длительности, включите **оба** переключателя видео. При пороге `0` все видео относятся к длинным и скачиваются, если включён `download_long_video`.

Выгрузка по ссылке сохраняет существующие MD и извлечённые JSON независимо от переключателей перезаписи. Если в ранее сохранённых диалогах не скачаны музыка или голосовые сообщения, включите их загрузку в настройках, сохраните настройки и нажмите **«Скачать недостающее аудио»**. Программа попробует скачать отсутствующие файлы по сохранённым ссылкам и добавит проигрыватели в сообщения; уже сохранённое аудио будет пропущено. При новой выгрузке включённые виды аудио скачиваются автоматически. Проверка качества фото и восстановление пропущенных видео выполняются при повторной генерации.

## Где лежат данные

```text
{export_root}/
├── ExportMessages/
│   ├── Sources/                      # Полученная история диалогов в JSON
│   ├── Dialogs/
│   │   ├── AutorImages/              # Аватары авторов
│   │   └── dialog_{peer_id}/          # Или пользовательское имя папки
│   │       ├── OriginalMessages/     # Отдельные сообщения в JSON
│   │       ├── MdFiles/              # Markdown
│   │       └── RawData/              # Фото, документы, аудио и другие вложения
│   ├── PhotoBackups/                 # Предыдущие фото и изменённые MD
│   ├── VideoBackups/                 # Предыдущие MD при восстановлении видео
│   └── AudioBackups/                 # Предыдущие MD при догрузке аудио
├── LargeRawData/
│   ├── dialog_{peer_id}/             # Видео из прежних выгрузок
│   └── SharedMedia/                 # Общие videos, images, audio, docs
└── MediaIndex.sqlite3               # Индекс видео, хешей файлов и аватаров
```

Рабочие файлы задач и локальное подключение браузера хранятся в `Temp/VkImport` рядом с конфигурацией. Папки `Temp`, `.venv`, `build` и `dist` исключены из Git. Для публикации настроек предусмотрен `config.example.json` без личных названий и идентификаторов диалогов; рабочий `config.json` следует подготовить отдельно.

## Повторное использование видео

Перед генерацией приложение проверяет все диалоги, включая прежние выгрузки. При повторных запусках перечитываются только изменённые сообщения. Индекс хранит относительные пути, поэтому весь архив можно перенести вместе с индексом.

Видео сопоставляются по паре `owner_id` + `id` ВК, а при отсутствии ID — по идентификатору или точному адресу плеера. Изменение временной CDN-ссылки не приводит к повторному скачиванию объекта с тем же ID. Если новое вложение требует более высокого разрешения, меньшая копия не подставляется.

Новые видео сохраняются в `LargeRawData/SharedMedia/videos`, Markdown и просмотрщик ссылаются на общий файл. Удаление сообщения или первого диалога не удаляет общий файл, используемый другими сообщениями. В редакторе общие вложения отображаются в списке **«Общие медиа»**; переименование общего файла из отдельного сообщения отключено.

После завершения генерации и догрузки аудио приложение проверяет вложения во всех диалогах по SHA-256. Полностью одинаковые фото, аудио, документы, видео и аватары получают один путь `LargeRawData/SharedMedia/{тип}/sha256_{хеш}.{расширение}`. Ссылки в Markdown обновляются, старые имена файлов удаляются, включая лишние жёсткие ссылки. Исходные JSON и пользовательские правки сообщений сохраняются. Перед заменой ссылок создаётся ZIP с прежним Markdown и перечнем перенесённых путей рядом с каталогом архива; медиа в него не копируются.

Разное содержимое и разные варианты качества автоматически не объединяются. Одинаковые байты объединяются и при разных ID вложений ВК. Во время активной загрузки временные копии могут существовать до завершающего объединения. Индекс можно восстановить повторным сканированием; он не заменяет исходные JSON или медиа.

## Другие способы запуска

Генерация из существующих JSON без браузера:

```powershell
.\.venv\Scripts\python.exe run.py --mode cli --config config.json
```

Стандартный веб-режим проекта:

```powershell
.\.venv\Scripts\python.exe run.py --mode web --config config.json --no-browser
```

У `run.py` есть параметры `--port`, `--config`, `--no-browser`. Например, для порта 8080: `python run.py --mode web --port 8080`. Подключайте помощник со страницы приложения на этом порту.

Сборка приложения: `build_exe.bat`. Шаблоны и исходники помощника включаются в сборку; ZIP для Chromium и Firefox формируется приложением при скачивании. Релизная сборка создаётся через `python tools/build_release.py`; она использует нейтральные настройки, а не личный config.json.

Ручная выгрузка через консоль ВК, загрузка JSON и выбор диалогов для генерации находятся в раскрывающемся блоке на странице **«Скачать диалог»**.

## Ограничения

- Сохраняются выбранные диалоги, а не полный архив всех данных аккаунта ВК.
- Качество ограничено копиями и ссылками, которые передал ВК. Приложение выбирает наибольшую доступную версию фото или MP4 и не перекодирует их для уменьшения размера.
- Удалённые или недоступные вложения, музыка без ссылки и видео внешних сервисов могут остаться ссылками. Подробности доступны в журнале.
- Предупреждения при загрузке по ссылке сохраняются в отдельном блоке «Предупреждения», даже когда ранние строки прогресса уже скрыты. Их количество относится ко всей загрузке; счётчики проверки фото и догрузки видео относятся к соответствующим этапам.
- Повторное использование сохранённых файлов не подтверждает их доступность на сервере ВК сегодня.
- Скорость зависит от CDN, сети и доступных ссылок. Параллельные запросы не гарантируют фиксированную скорость.
- Помощник зависит от браузерного интерфейса ВК; изменения сайта могут потребовать обновления расширения.
- HLS-аудио сохраняется в M4A через FFmpeg. Это отдельная обработка потокового аудио, а не изменение качества фотографий или MP4.

## Проверки

В текущем наборе — **70 тестов Python** и **23 теста браузерных скриптов**. Проверяются автоматическое определение браузера и выбор медиа, состояние кнопки подключения, сохранение файлов при повторном экспорте, восстановление вложений, объединение точных копий с обновлением ссылок, библиотека вложений и её границы диалога, сохранение ранних предупреждений, подробности ошибок и переходы к сообщениям, длинные пути, просмотр переписки, авторизация помощника и полнота полученной истории.

В блоке предупреждений новых выгрузок сохраняются адрес медиа, путь к файлу, номер сообщения, название вложения и причина ошибки. Для старых журналов, где адреса заменялись на `[ссылка]`, приложение отдельно показывает ссылки и номера сообщений из таблиц источников сохранённого архива. Эти сведения не подменяют исходный журнал; повторные попытки могут давать несколько предупреждений для одного вложения.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
node --test tests/test_chrome_helper.cjs tests/test_browser_detect.cjs tests/test_export_status.cjs tests/test_media_library.cjs tests/test_settings_media.cjs
```

Node.js нужен только для тестов JavaScript; сервер и выгрузка запускаются без него. Проверки и ручная проверка выгрузки выполнялись на Windows с Python 3.14 и обычным Chrome. Совместимость с другими системами отдельно не подтверждалась. Для Windows beta-сборка дополнительно проходит проверку запуска сервера и выдачи основных страниц; это не заменяет проверку всех сценариев реальной выгрузки.

В VK нет возможности сохранить переписку вместе с вложениями.<br>
**VkChatBackup** решает эту задачу: выгружает сообщения, конвертирует их в Markdown и скачивает все вложения.

Приложение полностью локальное — данные (исходные JSON, медиафайлы, Markdown-документы) остаются только на вашем компьютере и не передаются на внешние сервисы. Управление происходит через веб-редактор в браузере.

**Возможности:**
- Сохранение истории сообщений с указанием авторства и со всеми вложениями в markdown файлы (текст, фото, видео, документы, пересланные сообщения из других диалогов и сообществ)
- Веб редактор позволяет управлять markdown файлами (просмотр, переименование, удаление, группировка по папкам, массовые операции удаления и перемещения)
- Приложение работает локально, без пересылки данных в сторонние сервисы


## Быстрый старт

### Вариант 1: Бинарник (рекомендуется)

Скачайте бинарник из [релиза](../../releases), распакуйте и запустите `VkChatBackup.exe`. Браузер откроется автоматически. Python устанавливать не нужно.

### Вариант 2: Из исходников

1. Установите Python 3.9+ и зависимости:

   ```sh
   pip install -r requirements.txt
   ```

2. `config.json` уже есть в проекте — при необходимости отредактируйте (страница «Настройки» в веб-редакторе или вручную)
3. Запустите веб-редактор:

   ```sh
   python run.py --mode web --config config.json
   ```

4. Откройте `http://127.0.0.1:5000`

### Сборка бинарника (опционально)

Для сборки нужен PyInstaller — он входит в `requirements.txt`, поэтому достаточно установить зависимости (`pip install -r requirements.txt`).<br>
Скрипт `build_exe.bat` берёт PyInstaller из `.venv`, а если его там нет — глобальный.<br>
Результат: `dist/VkChatBackup/VkChatBackup.exe` + `_internal/` + `config.json`.

### Флаги запуска

| Флаг | Краткая | Описание | По умолчанию |
|---|---|---|---|
| `--mode` | | Режим запуска: `web` | `web` |
| `--port` | `-p` | Порт веб-сервера | `5000` |
| `--config` | `-c` | Путь к `config.json` | `config.json` рядом с приложением |
| `--no-browser` | `-nb` | Не открывать браузер автоматически | браузер открывается |

### Ярлык с флагами (Windows)

Чтобы запускать бинарник с переопределёнными флагами, создайте ярлык:

1. ПКМ на `VkChatBackup.exe` → **Создать ярлык**
2. ПКМ на созданном ярлыке → **Свойства**
3. В поле **Объект** допишите флаги после пути к exe:

   ```
   "C:\путь\к\VkChatBackup.exe" --mode web --port 8080 --config "C:\путь\к\config.json" --no-browser
   ```

   <div align="center">

     ![Настройка ярлыка](https://drive.google.com/uc?export=view&id=13AcWOjKeVH33L1ylWdsid931pK9jojyZ)
   </div>

4. Нажмите **ОК**. Теперь запуск через ярлык всегда будет с указанными флагами.

Примеры:

- Не открывать браузер: `"...\VkChatBackup.exe" --no-browser`
- Другой порт: `"...\VkChatBackup.exe" --port 8080`

**Как предстоит работать:**

1. **Выгрузка сообщений** — вручную через консоль браузера (скрипт формируется на странице «Экспорт»)
2. **Конвертация** — сообщения превращаются в Markdown, вложения скачиваются на диск
3. **Управление** — через веб-редактор: просмотр, переименование, удаление, группировка по папкам

Внутри веб-редактора есть подробная пошаговая инструкция (главная страница и страница «Экспорт») — следуйте ей.

## Рекомендации

- **Располагайте проект выше в иерархии.** Лимит длины пути — 255 символа: чем короче путь, тем больше места остаётся именам файлов
- **Первый экспорт сообщений.** При первом экспорте добавьте фильтр по дате сообщения, чтобы выгрузить только несколько сообщений для теста. 
> P.S. Конвертация большого количество сообщений и скачивания вложений может занять время. Мои 1600 сообщений конвертировались ~40 мин.

- **Используйте подпапки и сортировку** для группировки сообщений
- **Хранение файлов.** Предполагается, что файлы будут хранится в отдельном месте, для этого разделены RawData и LargeRawData.
>P.S. Я храню файлы в отдельном приватном GitHub репозитории.
Удобный просмотр в любое время, для редактирование открываю репозиторий в веб-редакторе.
- **Удаляйте мусор через веб-редактор** — доступны удаление, переименование, массовое переименование и перемещение файлов
- **Перемещайте файлы только через веб-редактор** — при перемещении ссылки заменяются автоматически
- **Не перемещайте файлы вручную** в файловом менеджере — слетят относительные ссылки
- **Не переименовывайте файлы вручную** — имена содержат важную информацию (например, cid сообщения)
- **Вложения переименовывайте тоже через редактор** — так ссылки в MD обновляются
- **Храните исходные JSON сообщений в `Sources/`** как бэкап — пригодится для повторной конвертации
- **Пользуйтесь фильтрами `min_cid` / `min_date`**, чтобы не выгружать лишние сообщения

## Структура файлов

```
{export_root}/
├── ExportMessages/
│   ├── Sources/                              # Исходные JSON-файлы сообщений
│   │   └── messages.json
│   └── Dialogs/
│       ├── AutorImages/                      # Аватары авторов
│       │   └── photo_12345.jpg
│       └── dialog_{peer_id}/ (или {custom_name})
│           ├── RawData/                      # Малые вложения (фото, стикеры, доки)
│           │   └── {cid}/
│           │       ├── 1.jpg
│           │       └── 2.webp
│           ├── OriginalMessages/             # Исходные JSON по одному сообщению
│           │   └── 2026-01-15_1234.json
│           └── MdFiles/                      # Сконвертированные Markdown-файлы
│               └── Привет.Id1234.md
└── LargeRawData/                             # Большие файлы (видео)
    └── dialog_{peer_id}/
        └── {cid}/
            └── 1.mp4
```

## FAQ

<details>
<summary><b>Как добавить сообщения к уже существующему диалогу?</b></summary>

Скачайте новый `messages.json` с более новыми сообщениями, поместите в `Sources/` и задайте фильтр `min_cid` / `min_date` на странице «Экспорт» — повторная конвертация добавит только новые сообщения.

</details>

<details>
<summary><b>Как добавить новый диалог?</b></summary>

Добавляется скачиванием нового файла `messages.json` с другим peer_id. Используйте инструкцию на странице `Export`.

</details>

<details>
<summary><b>Как переконвертировать диалог заново?</b></summary>

Включите флаги `overwrite_existing_md` и `overwrite_existing_original_message_json` на странице «Экспорт» (или в `config.json`).

</details>

<details>
<summary><b>Как полностью удалить сообщение?</b></summary>

В веб-редакторе, при просмотре md файла, нажать кнопку удаление в правом верхнем углу. Убирает MD-файл, вложения `RawData`/`LargeRawData` и исходный JSON.

</details>

<details>
<summary><b>Как переименовать папку диалога?</b></summary>

На странице диалога — кнопка ✏ рядом с названием папки.

</details>

<details>
<summary><b>Что за ограничение 255 символа?</b></summary>

Windows не допускает пути длиннее 255 символов. Длина учитывается для имён MD-файлов и вложений.

</details>

<details>
<summary><b>Как формируется имя MD-файла?</b></summary>

- **Есть текст** — имя = первое предложение сообщения + `.Id{cid}.md`, например `План мероприятия.Id1234.md`
- **Нет текста** — имя = тип вложения + дата + `.Id{cid}.md`, например `Photo.2026-01-15-12-34-56.Id1234.md`
  - префиксы типов: `Photo`, `Video`, `ShortVideo`, `Link`, `Article`, `Doc`, `Audio`, `Sticker`, `Media`
- **Только запись на стене без текста** — добавляется префикс `Статья`, например `Статья.Гайд по ревью кода от Google .Id1616.md`
- **Несколько записей на стене** — добавляется суффикс `_part_N`
- **Очистка имени**: убираются emoji и префиксы `@упоминаний`, `—` → `-`, спецсимволы `\/*?:"<>|` → `_`
- **Длинный текст** — обрезается под лимит пути 255 символа (остаётся минимум 10 символов текста)

</details>

<details>
<summary><b>Где взять peer_id?</b></summary>

В адресной строке диалога: `https://vk.ru/im/convo/{peer_id}`.

</details>

<details>
<summary><b>Что означает «Ошибка скачивания» в таблице «Источники»?</b></summary>

Вложение скачать не удалось (сетевой сбой, ограничения VK). В файле осталась только ссылка на оригинал.

</details>

<details>
<summary><b>Где хранятся вложения пересланных сообщений?</b></summary>

В `RawData/{root_cid}/{fwd_cid}/` — внутри каталога корневого сообщения.

</details>
